# Documentation and Architecture Conflicts

Facts identify sources and current behavior. “Decision required” does not choose policy.

| Conflict | Source A | Source B | Current code behaviour | Impact | Decision required | Safe interim behaviour |
|---|---|---|---|---|---|---|
| Workspace versus NOB/LOB | v1.1: Workspace is business area with NOB/LOB | RAK workbook names define NOB/LOB configuration; functional PDF text unavailable | workspace has `workspaceType`, `primaryNobId`; operations fixture labels LOB-like production | identifiers and readiness can be modeled wrongly | define whether Workspace is separate partition, site, NOB/LOB container, or mapping | keep IDs separate; do not infer conversions |
| Single versus multi-company user | legacy Arun `userMaster.company_id` | frontend `AuthSession.companies[]` and multi demo | frontend supports multi-company; Arun primary user company appears required | membership/context incompatible | define identity and membership model | explicit user-company relation; no implicit first company |
| 15 setup steps versus route count | `AGENTS.md` and onboarding docs say 15 | route map lists 13 route steps | `CompanySetup` supports 13 named routes | readiness cannot be authoritative | approve step list/mandatory flags | report only current completion; do not block on invented steps |
| Browser auth versus cookie session | old helpers/legacy callers | authentication contract | **Resolved in mock M1:** only cookie-backed `AuthContext`; old snapshot/helpers removed | backend still uses a different transport | choose production direct implementation or server adapter | preserve the typed cookie-session frontend contract |
| Company-only versus workspace operations | old `/{company}/batches` routes | v1.1 canonical nested workspace routes | legacy resolvers auto-select one workspace | stale context and accidental implicit scope | confirm canonical URL and migration window | only explicit resolver; no new company-only APIs |
| Tenant URL versus per-tenant DB | endpoint matrix includes tenant URL segment | Arun connection manager chooses tenant database/header | frontend requires tuple URL; backend database boundary hides scope | backend cannot prove tuple path scope | select external API tenancy convention | validate tenant/company/workspace server-side regardless of URL |
| Readiness definitions | onboarding flow splits foundation/accounting/operations | readiness policy remains partly unresolved | **Resolved in mock M2:** company aggregate keeps foundation/setup/masters/accounting/workspaces separate and links the dedicated accounting page | backend can still misclassify blockers | define production resources and gates | policy-pending rules remain non-blocking |
| Standard versus custom company roles | documented role examples | final custom-role catalogue absent | **Resolved in mock M2:** standard company/workspace catalogues are separate; custom roles display planned only | pretending to persist custom roles would create false authorization behavior | define custom permission, delegation, audit and lifecycle policy | assign standard company roles in Members; no custom mutation |
| Tenant Admin authority | permission docs: configuration, no implicit operations | earlier mock precheck accepted tenant/company admin | **Resolved in mock M1:** exact active-workspace capabilities authorize operations | product/backend policy still needs persistence | define configuration/accounting overrides, never implicit operations | explicit workspace role/capability for all operations |
| Backend v1/v2 vertical duplication | `origin/arun.pratap` app module imports old and v2 modules | frontend has one neutral workspace workflow | duplicate owners may expose competing APIs | unstable integration target | nominate canonical backend modules per vertical | no frontend binding to either until chosen |
| Old agent guidance/product phase | `AGENTS.md`: frontend demo, backend another developer | root README and Arun branch: broad backend modules | repository contains both messages | contributors can overstate production state | update ownership/phase statement | treat mock and backend reference as separate evidence |
| Error contract | `docs/api-contract/error-contract.md` requires `{error:{...requestId,timestamp}}` | Arun `HttpExceptionFilter`/controllers often return legacy `{success,message,data}` forms | client has legacy fallback parser | forms cannot rely on field errors/request IDs | adopt envelope or version bridge | do not mark arbitrary legacy payloads contract-compatible |
| Operational path statement | state-machine close text says `/companies/[c]/batches/...` | operational client uses `/tenants/[t]/companies/[c]/workspaces/[w]/...` | implementation follows latter | docs conflict masks scope requirement | correct state-machine documentation | retain client path as current frontend fact |
