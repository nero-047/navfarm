## 1. Project Overview

**System**: NAVFarm ERP — Multi-Tenant SaaS Agricultural ERP  
**Stack**: NestJS · MySQL (Drizzle ORM) · JWT Authentication · Per-Tenant Database Isolation  
**Base URL**: `http://localhost:3000` (development) · `https://api.navfarm.com` (production)  
**API Prefix**: `/api/v1` (note: verify global prefix in `main.ts`)  
**Swagger UI**: `http://localhost:3000/api/docs`

---

## 2. API Conventions

| Convention | Value |
|---|---|
| Protocol | HTTPS (TLS 1.2+) |
| Content-Type | `application/json` |
| Date Format | ISO 8601: `YYYY-MM-DD` / `YYYY-MM-DDTHH:mm:ssZ` |
| UUID Format | v4 UUID (`xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx`) |
| Soft Delete | Records are deactivated not destroyed; use `PATCH /:id/restore` to recover |
| Idempotency | POST operations on document posting (`/post`) are idempotent once POSTED |
| Versioning | URL-based (`/api/v1`) |

---

## 3. Authentication & Authorization

### Flow

```
POST /auth/login → { token, refresh_token, tenantId, user }
                         ↓
              Store in secure storage
                         ↓
         Inject into all subsequent requests:
         Authorization: Bearer <token>
```

### Token Lifecycle

| Token | Lifetime | Usage |
|---|---|---|
| Access Token (JWT) | 15 minutes (configurable) | All protected endpoints |
| Refresh Token | 7 days | `POST /auth/refresh` only |

### MFA Flow (Optional)

```
POST /auth/login  →  { mfaRequired: true, tempToken }
POST /auth/mfa/qr →  { qrUri, secret }   (first-time setup)
POST /auth/mfa/verify → { token, refresh_token }  (each login)
```

### Guards Active in Backend

| Guard | Effect |
|---|---|
| `JwtAuthGuard` | Validates Bearer JWT; sets `req.user` |
| `SystemAdminGuard` | Restricts to `userType === 'SYSTEM_ADMIN'` |
| `RolesGuard` | Validates `@RequirePermission(module, resource, action)` |

---

## 4. Common Request Headers

```http
Authorization: Bearer <JWT_ACCESS_TOKEN>    # Required on all protected routes
Content-Type: application/json              # Required on POST/PUT/PATCH
```

> **Note**: Tenant context is resolved automatically from the JWT `tenantId` claim. No `X-Tenant-Id` header is required on most endpoints. The `tenantId` is embedded in the JWT payload.

---

## 5. Standard Response Envelope

Every endpoint returns this wrapper:

```json
{
  "success": true,
  "message": "Human-readable status message.",
  "data": { },
  "meta": {
    "page": 1,
    "limit": 20,
    "total": 150,
    "hasNext": true
  }
}
```

- `data` may be an object, array, or `null`
- `meta` is only present on paginated list responses
- `success: false` indicates a business-logic failure (not an HTTP error)

---

## 6. Error Response Format

```json
{
  "success": false,
  "statusCode": 400,
  "message": "Validation failed",
  "errors": [
    {
      "property": "email",
      "constraints": {
        "isEmail": "email must be a valid email address"
      }
    }
  ]
}
```

### HTTP Status Codes

| Code | Meaning |
|---|---|
| `200` | OK — Read/Update succeeded |
| `201` | Created — Resource created |
| `400` | Bad Request — Validation error in body/params |
| `401` | Unauthorized — Missing or invalid JWT |
| `403` | Forbidden — Valid JWT but insufficient permissions |
| `404` | Not Found — Resource does not exist |
| `409` | Conflict — Duplicate unique value (e.g. same code) |
| `422` | Unprocessable Entity — Business rule violation |
| `500` | Internal Server Error |

## 7. Pagination, Filtering & Sorting

### Query Parameters (Standard)

| Parameter | Type | Default | Description |
|---|---|---|---|
| `limit` | `integer` | `20` or `50` | Results per page |
| `offset` | `integer` | `0` | Skip N records |
| `search` | `string` | — | Free-text search across name/code fields |
| `isActive` | `boolean` | — | Filter by active status |
| `companyId` | `uuid` | — | Filter by company (where applicable) |
| `sortBy` | `string` | — | Field name to sort by |
| `sortOrder` | `ASC\|DESC` | `ASC` | Sort direction |

### Frontend Integration Notes

- Use `debounce(300ms)` on search inputs before firing API calls
- Implement **TanStack Query** (`useInfiniteQuery`) for infinite scroll
- Set `staleTime: 30000` for master data (items, warehouses, customers)
- Invalidate cache on any mutation using `queryClient.invalidateQueries()`

# MODULE 01 — Authentication (`/auth`)

**Business Purpose**: Authenticate users, issue JWT tokens, manage MFA, and list tenant users.  
**Dependencies**: None (public endpoints for login/register)  
**DB Tables**: `user_master`, `tenant_master`

---

### POST `/auth/register-admin`

**Summary**: Register the initial Company Admin (Step 9 of onboarding wizard).  
**Auth**: No JWT required (but called with a wizard token from setup flow).

**Request Body**:
```json
{
  "email": "admin@greenvalley.com",
  "password_hash": "SecurePassword123!",
  "full_name": "Rajesh Kumar Sharma",
  "phone": "+919999999999",
  "tenant_id": "123e4567-e89b-12d3-a456-426614174000",
  "company_id": "456e4567-e89b-12d3-a456-426614174000",
  "timezone_pref_id": "Asia/Kolkata",
  "user_type": "STANDARD_USER"
}
```

| Field | Type | Required | Validation |
|---|---|---|---|
| `email` | string | ✅ | Valid email, unique per tenant |
| `password_hash` | string | ✅ | Min 8 characters |
| `full_name` | string | ✅ | Non-empty string |
| `phone` | string | ❌ | Optional phone number |
| `tenant_id` | uuid | ✅ | Must exist in `tenant_master` |
| `company_id` | uuid | ✅ | Must exist in `company_master` |
| `timezone_pref_id` | string | ✅ | Valid IANA timezone string |
| `user_type` | string | ❌ | Defaults to `STANDARD_USER` |

**Success Response (201)**:
```json
{
  "success": true,
  "message": "Administrative account created successfully.",
  "data": {
    "userId": "user-uuid",
    "email": "admin@greenvalley.com",
    "full_name": "Rajesh Kumar Sharma"
  }
}
```

**Error Responses**:
- `409` — Email address already exists in this tenant

---

### POST `/auth/login`

**Summary**: Authenticate credentials and get JWT token pair.  
**Auth**: None (public).

**Request Body**:
```json
{
  "email": "admin@greenvalley.com",
  "password": "SecurePassword123!"
}
```

| Field | Type | Required | Validation |
|---|---|---|---|
| `email` | string | ✅ | Valid email format |
| `password` | string | ✅ | Non-empty |

**Success Response (200)**:
```json
{
  "success": true,
  "message": "Login successful.",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "mfaRequired": false,
    "tenantId": "00000000-0000-0000-0000-000000000000",
    "user": {
      "userId": "user-uuid",
      "email": "admin@greenvalley.com",
      "role": "TENANT_ADMIN",
      "userType": "STANDARD_USER"
    }
  }
}
```

> **MFA Response** (when MFA enabled):
```json
{
  "success": true,
  "data": { "mfaRequired": true, "tempToken": "..." }
}
```

**Error Responses**:
- `401` — Invalid email or password

**Frontend Integration**:
```typescript
// Axios call
const { data } = await api.post('/auth/login', { email, password });
localStorage.setItem('token', data.data.token);
localStorage.setItem('refresh_token', data.data.refresh_token);
api.defaults.headers.common['Authorization'] = `Bearer ${data.data.token}`;

// React Query hook
export const useLogin = () => useMutation((payload) => api.post('/auth/login', payload));
```

# MODULE 37 — Finance: Journals (`/finance/journal`)

**Business Purpose**: Manual double-entry journal creation and posting. Every journal requires balanced lines (Sum(Debits) == Sum(Credits)).  
**Permission**: `FINANCE / JOURNAL / create|view`  
**DB Tables**: `financial_journal`, `financial_journal_line`, `general_ledger_entry`

---

### POST `/finance/journal`

**Summary**: Create a balanced manual journal draft.

**Request Body**:
```json
{
  "company_id": "company-uuid",
  "journal_type": "GENERAL",
  "posting_date": "2026-07-27",
  "notes": "Monthly depreciation entry",
  "lines": [
    {
      "gl_account_id": "depreciation-expense-uuid",
      "debit": 5000.00,
      "credit": 0,
      "description": "Equipment depreciation",
      "cost_center_id": "cc-uuid",
      "dimension_values": { "FARM": "FarmA" }
    },
    {
      "gl_account_id": "accumulated-depreciation-uuid",
      "debit": 0,
      "credit": 5000.00,
      "description": "Accumulated depreciation credit",
      "cost_center_id": "cc-uuid"
    }
  ]
}
```

| Field | Type | Required | Description |
|---|---|---|---|
| `journal_type` | string | ✅ | `GENERAL`, `PURCHASE`, `SALES`, `PAYMENT`, `RECEIPT`, `ADJUSTMENT`, `INVENTORY` |
| `posting_date` | date | ✅ | Must fall in an open accounting period |
| `lines[].gl_account_id` | uuid | ✅ | Must be a leaf (postable) account |
| `lines[].debit` | decimal | ❌ | Either debit or credit must be > 0 (not both) |
| `lines[].credit` | decimal | ❌ | Either debit or credit must be > 0 (not both) |
| `lines[].cost_center_id` | uuid | ❌ | Required if account has `cost_center_required = true` |
| `lines[].dimension_values` | object | ❌ | Required if account has `dimension_required = true` |

**Validation Rules**:
- `SUM(lines.debit) MUST === SUM(lines.credit)` — rejects if unbalanced
- Each line: either `debit > 0, credit = 0` OR `debit = 0, credit > 0`
- Posting date cannot fall in a locked period
- GL accounts must be active leaf accounts (non-parent)

**Success Response (201)**:
```json
{
  "success": true,
  "message": "Financial Journal registered as DRAFT.",
  "data": {
    "journal_id": "jnl-uuid",

  }
}
```

3. Writes immutable `general_ledger_entry` rows with running balances
4. Updates journal status → `POSTED`

**Success Response (200)**:

**Error Responses**:

# Integration Flow Examples

## Flow 1: Login → Company Selection → Dashboard

```
1. POST /auth/login
   → { token, tenantId, user }

2. GET /user-company/assignments
   → [{ company_id, company_name }]

3. User selects active company → store companyId in context

4. GET /inventory/balance?itemId=...&warehouseId=...&locationId=...
   GET /finance/report/trial-balance?companyId=...&startDate=...&endDate=...
   → Dashboard KPIs populated
```

## Flow 2: Complete Goods Receipt Posting

```
1. GET /warehouse?companyId=...  → Select warehouse
2. GET /supplier?companyId=...   → Select supplier
3. GET /item?companyId=...       → Select items for lines
4. GET /location?warehouseId=... → Select bin locations

5. POST /inventory/goods-receipt → { receipt_id, status: "DRAFT" }
6. POST /inventory/goods-receipt/:id/post
   → Stock committed + GL entries written automatically
```

## Flow 3: Month-End Close

```
1. GET /finance/fiscal/year?companyId=...
   → Identify active fiscal year and periods

2. GET /finance/report/trial-balance?...  → Review balances
3. POST /finance/journal  → Post month-end accruals / depreciation
4. POST /finance/journal/:id/post         → Commit to GL

5. POST /finance/fiscal/period/:id/close  → Lock the month

6. GET /finance/report/balance-sheet?...  → Final statements
7. GET /finance/report/profit-loss?...    → P&L report
```
